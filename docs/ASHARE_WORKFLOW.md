# A 股研究与本地模拟工作流

此项目把研究假设、按时间划分的数据、参数选择、回测和本地模拟账本串成可复现的演示。真实 A 股数据接入、完整历史股票池、公司行动、实际容量与券商执行需要在研究时逐项补足。

## 先跑通工程流程

```bash
bash scripts/setup.sh minimal
bash scripts/run.sh demo --output artifacts/demo --seed 42
.venv/bin/python -m pytest
```

演示生成固定股票池的合成日线，在训练区间选择动量回看参数，随后检查保留样本，输出订单、成交、资金曲线和模拟账本。它能暴露数据排序、信号时间、费用、账户状态和恢复流程中的错误。合成收益、模拟回撤和候选参数均不能用于判断真实市场是否存在可交易优势。

## 固定研究问题与检验方法

在读取保留样本结果前，保存一份假设记录，至少写明研究问题、机制解释、候选参数、股票池、信号时刻、预计成交时刻、样本切分、比较基准和失败条件。记录所有尝试过的假设与参数，防止只保留表现好的运行。`hypothesis.yaml` 展示记录形式；真实实验应在运行前单独版本化。

按日期切分训练、验证和最终保留区间。特征标准化、缺失处理及参数选择只在允许的历史区间拟合；再以冻结设置评估后续区间。多次滚动检验时记录每一折的训练截止日、预测区间、代码提交、数据快照和参数。若不断根据保留区间的结果修改策略，它就已经成为新的调参数据，需要另留检验区间。

## 真实数据需要的时间与范围

| 数据 | 准备方法 | 避免的问题 |
| --- | --- | --- |
| 交易日历 | 使用对应交易所的真实开市日与交易时段 | 把节假日当成交易日、错误计算 T+1 |
| 股票与历史成分 | 保存上市、退市、状态变化与历史成分生效日 | 只研究当前存续股票形成幸存者偏差 |
| 行情 | 保存来源、下载时间、原始单位、价格口径和缺失原因 | 成交量单位错位、停牌误判、数据回填 |
| 财务与公告 | 按首次公开可得时间连接，保留修订版本 | 用报告期末日或后来修订值提前预测 |
| 公司行动与复权 | 分离信号价格、真实成交价格、持仓与现金调整 | 把复权价格当订单价格、忽略分红送转 |
| 可交易状态 | 按日期保存停牌、风险警示、限价和账户可交易范围 | 将有行情等同于可成交 |

例如 TuShare `stock_basic` 提供上市及退市字段，但默认查询当前上市状态；历史研究需覆盖退市等状态并构建当时可得股票池。[股票信息 API](https://tushare.pro/document/2?doc_id=25) 工作日日期序列应替换成真实 `trade_cal` 开市日。[交易日历 API](https://tushare.pro/document/2?doc_id=26)

TuShare `daily` 是未复权行情，停牌期间没有该接口的行情记录，成交量和成交额另有单位；合并时应显式转换和处理缺失。[日线 API](https://tushare.pro/document/2?doc_id=27) `adj_factor` 是另一组数据，研究特征的复权口径需固定并记录；该演示不会自动执行分红、拆股或送转的完整账户处理。[复权因子 API](https://tushare.pro/document/2?doc_id=28)

财务指标的 `ann_date` 与 `end_date` 分别描述公告日期和报告期。工程上应以可得时间约束特征连接；只有日期时，可采用下一交易日可用等明确保守约定，并核查实际发布时刻、修订版本和供应商数据口径。[财务指标 API](https://tushare.pro/document/2?doc_id=79)

TuShare 某些接口要求积分或额外权限，RQData 有账户许可证和流量配额；本项目安装客户端不会开通这些权限。[TuShare 权限示例](https://tushare.pro/document/2?doc_id=79) [RQData 账户与配额](https://www.ricequant.com/doc/rqdata/python/manual.html)

## 信号、成交与交易约束

日线策略应把已知信息生成信号与下次允许交易的成交时刻分开。用收盘后才可获得的数据生成信号，再按同一日开盘价成交，会引入未来信息。回测应保存信号生成日期、委托日期、成交日期和拒绝理由，并用小样本手工核对现金与持仓。

演示包含可配置费用与滑点，默认采用 100 股整数单位、T+1、停牌和给定价格限制。这些是工程简化。真实市场应按股票所属板块、交易日期、账户权限和具体业务匹配最小申报数量与限价条件；例如上交所现行规则对科创板限价申报规定不同的最小股数，不能把全市场一律当作 100 股规则。[上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)

尽量导入每日实际涨跌停价格，避免对全部股票硬编码单一比例。TuShare `stk_limit` 可提供逐日涨跌停价格，但可取到限价不等于该价格一定能成交。[涨跌停 API](https://tushare.pro/document/2?doc_id=183) 演示在开盘触及相应限制时保守阻止订单，未模拟盘口排队、部分成交、成交量参与率、冲击成本和涨停板成交机会。

配置中的佣金最低费用、过户费、卖出税费和滑点是可调示例值，不能视为当前券商真实费率。替换数据时应根据研究时期和账户收费设置，并比较不同成本与容量假设下的结果。

## 从回测进入本地模拟

先冻结研究设置，保留订单账、成交账、现金、持仓与复核指标，再用相同撮合条件回放数据：

```bash
bash scripts/run.sh paper \
  --data artifacts/demo/data/synthetic_prices.csv \
  --database artifacts/paper/paper.sqlite \
  --config configs/research.yaml \
  --lookback 20 \
  --mode local-paper
```

CSV 的必填列如下；同一 `date/symbol` 只能有一行，价格必须是有限正数并符合所给上下限。输入必须覆盖固定股票池的完整日线面板，缺失记录需显式处理为停牌与估值记录。

| 列 | 约定 |
| --- | --- |
| `date` | ISO 格式交易日，如 `2026-09-30` |
| `symbol` | 保留交易所信息的一致证券代码 |
| `open`、`close` | 未复权、可交易价格 |
| `upper_limit`、`lower_limit` | 当日价格上下限 |
| `suspended` | `true/false` 或 `1/0` |

`previous_close`、`volume` 以及其他附加列可以保留，但当前引擎不使用这些列进行成交量约束或公司行动处理。原始 CSV 的换算和验证仍由数据接入方负责。

命令使用指定 SQLite 文件保存状态与检查点。每日订单、估值、现金及持仓批次在同一事务中提交；相同数据、配置、信号及起止范围的重复调用从检查点恢复，不重复入账。运行标识绑定完整输入：增加数据行或修改参数会创建新的隔离运行，不能把它当作对同一实时账户的增量更新。停止、继续与重复输入时，应核对账本是否出现重复订单、重复现金变动及过期行情。

当前实现是 CSV 驱动的本地回放，不会持续订阅行情或向券商报单。按日持续模拟需要额外数据更新与调度服务、交易日历、持久存储、并发控制、失败重试和监控；部署方法见 [Cloud 配置](CLOUD_SETUP.md)。完成这些以后，再以模拟账户逐笔核对执行与账本行为，才能评估后续系统需求。

## 每次运行留下可检查的记录

至少保存代码提交、锁文件版本、数据来源与快照、随机种子、假设记录、训练截止日、参数选择过程、订单拒绝原因和成本设定。比较基准、换手、暴露、回撤、交易容量以及不同时间区间的表现；不能只检查单一累计收益。演示的 `manifest.json` 与各阶段 CSV/JSON 为这些记录提供了起点。
